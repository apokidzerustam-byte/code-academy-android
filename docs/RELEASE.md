# Выпуск версии и ключ подписи

## Два «канала» и два ключа
| Канал | Откуда ставить | Чем подписан | Для чего |
| --- | --- | --- | --- |
| Прототип | ветка `apk` (`code-academy-proto.apk`), обновляется после каждой успешной сборки `main` | публичный ключ `signing/prototype.keystore` (пароль `android`) | проверка на телефоне заказчика, обновление «поверх» |
| Релиз | страница Releases (APK прикладывается к черновику релиза) | релизный ключ из секретов репозитория | распространение |

**Ключ прототипа публичен** (лежит в репозитории): любой может собрать APK с той же подписью. Для распространения он не подходит.
Если секреты релизного ключа не заданы, сборка тега подписывается ключом прототипа, а релиз автоматически помечается «Pre-release»
с предупреждением. Это сделано намеренно: нельзя случайно выпустить «настоящий» релиз с публичным ключом.

## Главный риск: смена ключа
Android ставит новую версию поверх старой только если подпись совпадает. APK, подписанный релизным ключом, **не встанет поверх** установленного
прототипа: придётся удалить приложение, а при удалении данные пропадают. Порядок для телефона, где уже стоит прототип:
1. Настройки → «Данные и резервная копия» → «Сохранить копию» (файл в «Загрузки» или на диск).
2. Удалить Code Academy, установить релизный APK.
3. Настройки → «Данные и резервная копия» → «Восстановить» → выбрать сохранённый файл.
Канал `apk` (прототип) остаётся на прототипном ключе, поэтому телефон заказчика продолжит обновляться без потери данных, пока заказчик сам не перейдёт на релизный.
Релизный ключ используется **только** при сборке тега `v*`.

## Создание релизного ключа (один раз)
Ключ создаёт владелец; в репозиторий и в чат он не попадает.
На телефоне в Termux:
```
pkg update && pkg install openjdk-17
keytool -genkeypair -v -keystore release.keystore -alias codeacademy -keyalg RSA -keysize 4096 -validity 36500
base64 -w0 release.keystore
```
`keytool` спросит пароль (запомните его) и имя/организацию (можно любые). Последняя команда выводит длинную строку — это ключ в текстовом виде.
Затем GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret. Создайте секреты:
| Имя | Значение |
| --- | --- |
| `CA_RELEASE_KEYSTORE_B64` | строка из `base64 -w0` |
| `CA_RELEASE_STORE_PASSWORD` | пароль хранилища |
| `CA_RELEASE_KEY_ALIAS` | `codeacademy` |
| `CA_RELEASE_KEY_PASSWORD` | пароль ключа (если вводили отдельный; иначе можно не создавать) |

**Сохраните `release.keystore` и пароли в надёжном месте (менеджер паролей, облако с шифрованием) и не в репозитории.**
Потеря ключа = невозможность обновлять установленные у людей копии: придётся выпускать приложение под новым ключом и просить всех удалить старое.

## Выпуск версии
1. GitHub → Actions → «Выпуск (тег и черновик релиза)» → Run workflow → введите версию (например `0.10.0`) → Run.
2. Workflow создаст тег `v0.10.0` на текущем `main` и запустит полную сборку с тестами (JVM, эмуляторы API 29 и 34, наставник с настоящими моделями, аудит APK).
3. Если всё зелёное, в Releases появится **черновик** «Code Academy 0.10.0»: APK `code-academy-0.10.0.apk`, `SHA256SUMS.txt`, `audit.md`
   (результат аудита), `dependencies.txt` (версии зависимостей), `LICENSES.md`, заметки из `docs/CHANGELOG.md`; исходники GitHub прикладывает сам.
4. Откройте черновик, проверьте вложения и подпись в `audit.md` (строка «Подпись: … релизный ключ»), и только тогда нажмите **Publish release**.
   Публикует владелец: автоматически ничего не публикуется.
Если тесты красные, черновик не создаётся. Тег можно удалить (Code → Tags) и выпустить заново после исправления.

## Что проверяет аудит APK (`ci/audit_apk.py`)
Нет разрешений на сеть и личные данные; открыта наружу только главная Activity; не debuggable; `allowBackup=false`; иконки заданы; minSdk 26 / targetSdk 35;
подпись проверена `apksigner` (схемы v2/v3) и определён тип ключа; в APK нет ключей и сырых записей голоса; выравнивание .so под страницы 16 КБ (предупреждение);
разбор размера по частям. Нарушения (❌) останавливают сборку, предупреждения (⚠️) — нет.

## Почему R8 (сжатие кода) выключен
Chaquopy, мост Pyodide, JNI и kotlinx.serialization требуют отдельных правил сохранения классов, а выигрыш мал: APK ≈ 150 МБ почти целиком — Python/Pyodide,
нативные библиотеки llama.cpp и аудио уроков, код — единицы мегабайт. Риск поломки больше выигрыша; решение пересматривается, если размер кода станет заметным.
